INDIAN JEWELLERY ? WEBSITE REQUIREMENTS AND PROJECT SETUP
Updated: 2026-09-14

1. SCOPE AND STATUS
Build a responsive Indian jewellery storefront in Next.js and TypeScript.
Application development is restricted to jewelleryfrontend/.
Root requirements, design-system and typography folders contain project documentation.
backend/ and adminpanel/ are reserved and have no implementation in this task.
The current site is a frontend preview using local sample data, not a live commerce service.
Do not imply that authentication, payments, orders or newsletter subscriptions are live.

2. DOCUMENTATION SOURCES
requirements/requirements.txt: website scope, functionality, setup and acceptance criteria.
design-system/design-system.md: canonical supplied global visual system and approved exceptions.
typography/typography.md: font configuration and type hierarchy.
jewelleryfrontend/README.md: developer quick start.
jewelleryfrontend/docs/design-system.md: implementation mapping to canonical rules.
jewelleryfrontend/docs/storefront-implementation.md: homepage component map and behavior.
jewelleryfrontend/docs/assets.md: existing local image provenance.
Keep these filenames; do not create competing requierment.txt or typographic.md copies.

3. TECHNICAL STACK
Next.js 16.3.4 App Router; React 19.2.8; TypeScript 5.
Tailwind CSS 4 with @tailwindcss/postcss; global CSS and scoped CSS Modules.
Lucide React for icons; Zustand for browser-persisted cart and wishlist.
React Hook Form + Zod + @hookform/resolvers for frontend form validation.
ESLint with eslint-config-next; Prettier; @playwright/test for browser verification.
package.json and package-lock.json are the dependency source of truth.
No additional carousel, icon, image or styling package is required.
Read jewelleryfrontend/AGENTS.md and the installed Next.js docs before changing framework code.

4. LOCAL SETUP
Validated development runtime: Node.js v24.21.0 and npm 10.9.0.
From repository root:
  cd jewelleryfrontend
  npm ci
  npm run dev
Open http://localhost:3000.
Alternative port: npm run dev -- --port 3001.
For production preview: npm run build, then npm start.
No environment variables, API keys or database are required for the frontend preview.
Google Fonts are configured through next/font/google; dependency installation and a fresh
font build require internet access. Product imagery is served locally from public/images/.
Do not commit node_modules/, .next/, artifacts/ or secrets.

8. NEW LAUNCH ACCEPTANCE CRITERIA
Centered NEW LAUNCH h2 with balanced thin gold rules on each side.
Multi-card horizontal carousel, never a single full-width hero.
Desktop (1024px+): three complete cards plus a quarter of the next card.
Tablet (768?1023px): two complete cards plus a quarter of the next card.
Mobile (320?767px): one complete card plus a small portion of the next card.
Use equal CSS gaps: desktop 24px, tablet 16px, mobile 12px.
Use the existing homepage gutter; keep both outer edges balanced.
Cards share a 4:5 aspect ratio and full-bleed centered cover images with no distortion.
Titles and SHOP NOW links remain inside the card over the image, aligned consistently.
Use existing imagery: necklace, earrings, silver, ring; no separate reference image was supplied.
Titles: Pillars of Time; Leafy Affair; Fractals In Nature; Timeless Radiance.
Each item has id, image, alt, title, buttonText and link; render with map, not duplicate markup.
Expose reusable NewLaunchSection, NewLaunchCarousel and NewLaunchCard components.
NewLaunchSection accepts optional items so future API data can replace local data.
Empty data hides the section; a single card does not render navigation arrows.
Previous/next controls are circular, vertically centered, labeled and keyboard accessible.
Arrow controls move by a measured card plus gap. End controls rewind to the opposite end;
this is not a cloned infinite carousel. Native touch/swipe and mouse dragging are supported.
ArrowLeft/ArrowRight and Home/End work when the carousel or its links have focus.
Respect reduced motion; no carousel autoplay is required.
Only the carousel scrolls horizontally. Never create page-level horizontal overflow.
Do not modify other homepage sections to implement this feature.

9. ROUTES AND DISCOVERY
/: complete homepage.
/collections and /collections/[slug]: collection discovery with breadcrumb and heading.
/category/[slug]: the ten homepage categories; empty inventory shows an empty state.
/best-sellers, /wedding, /precious, /precious/lab-grown-diamonds: campaign/category browsers.
/product/[id] and /products/[slug]: product detail routes for known catalog IDs.
/search: search results; /wishlist: saved products; /cart: bag.
/checkout and /account: frontend previews with explicit unavailable backend actions.
/help/[slug] and /about/[slug]: supporting information for known slugs.
Unknown products/categories/pages use the existing not-found behavior.
Collection filters: category, material/purity, gemstone, occasion, collection badge,
maximum price and availability. Sorting: featured, price ascending/descending,
bestselling and newest. Mobile filters use the existing modal.
Some campaign aliases share the full sample catalog; do not claim live merchandising.

10. PRODUCT AND SHOPPING BEHAVIOR
Products contain ID, name, category, price, MRP, image, material, gemstone, occasion,
badge, sample rating/review count, availability and description.
Display INR prices, original prices and calculated discount percentages.
Detail page includes image zoom, quantity/size selection, wishlist, add-to-bag,
product details and delivery lookup preview. Unavailable stock must not be purchasable.
Bag supports quantity updates (1?10), removal, totals and the existing coupon preview.
Cart/wishlist persist in localStorage under techglock-shop with explicit hydration.
Checkout validates name, email, Indian mobile number, address, city, state and pincode.
It only shows a review preview: no payment, order or server submission occurs.
Account and newsletter remain previews; do not invent authentication or subscription success.

11. GLOBAL VISUAL AND TYPOGRAPHY RULES
Follow design-system/design-system.md for every new UI surface.
Emerald #0D3B2E, deep emerald #082C22, gold #C69C45, light gold #E8D5A8,
ivory #FDFCF8, beige #F4F0E8, white #FFFFFF and semantic text/border colors.
Use CSS variables, the 4px spacing scale and existing component tokens.
Cormorant Garamond for display headings; Inter for interface and body, weights 400/500/600.
Load fonts once through the existing root layout. No new fonts or icon libraries.
Restrained radii, minimal shadows, readable hierarchy and subtle 180ms interactions.
Preserve the approved featured-card border removal, reduced image height and tighter spacing.
Global future defaults do not override explicit section refinements.
Dark-theme tokens exist but full active storefront dark-mode support is not completed.

12. ACCESSIBILITY, RESPONSIVENESS AND PERFORMANCE
Semantic headings, meaningful alt text, labeled controls, visible focus and keyboard access.
At least 44px interactive carousel controls, natural touch scrolling and reduced-motion support.
Test 320, 390, 768, 1024, 1280 and 1440px widths, plus resizing and page zoom.
Avoid horizontal page overflow, clipped CTA text, distorted imagery and stale arrow steps.
Use next/image with fill inside a sized positioned parent and responsive sizes.
Lazy-load below-fold images; do not preload every carousel image.
Use local assets and no unnecessary dependencies. Keep client boundaries limited to interaction.
Preserve existing metadata, product structured data, loading, error and not-found handling.

15. ADMIN MYSQL INTEGRATION (2026-09-16)
Explicitly authorized scope: adminpanel/ Next.js + TypeScript and backend/ Node.js + Express + MySQL.
Storefront implementation remains unchanged. Follow the canonical design system.
All catalog/sidebar sections use authenticated Express APIs rather than browser IndexedDB.
Catalog fields, status, ordering, images and videos persist in MySQL. Start with empty records;
do not silently turn sample orders/customers into live records or migrate browser data.
Dashboard, orders, returns, customers, payments and shipping read persisted workspace records.
Inventory: searchable, filtered, paginated product/SKU/category details; current, sold and
available stock; stock value at selling price; validated stock adjustment with conflict checks.
Analytics shows all-time saved-order/customer totals. Settings saves store name, contact email
and low-stock threshold. Empty order data stays empty; checkout/payment ingestion is out of scope.
Use HTTP-only admin sessions, server-side administrator checks and no public admin signup.
Persist workspace updates atomically with a revision check. Media is stored as MySQL blobs.
MySQL schema and migrations live in backend/prisma/mysql; original PostgreSQL history is preserved.
Admin layouts use compact 4px-scale spacing, 32px desktop/28px mobile headings and existing fonts.
Do not shrink controls or remove fields to reduce scrolling. Inventory uses eight rows per page.
Local setup requires a MySQL DATABASE_URL, ADMIN_SESSION_SECRET and a provisioned administrator.
See backend/ADMIN-SETUP.md. Browser API-fixture tests do not prove live MySQL connectivity.

16. INITIAL ADMIN SIGNUP (2026-09-16)
Login links to /admin/signup. Signup posts name, email and password to Express /admin-api/signup.
Initial signup creates the first administrator and an HTTP-only session, then opens the dashboard.
A transaction and durable setup marker prevent repeated bootstrap registration; existing admin
accounts must sign in. Production initial signup requires ADMIN_ALLOW_INITIAL_SIGNUP=true during setup.
MySQL configuration, migrations and ADMIN_SESSION_SECRET remain prerequisites.
This supersedes the CLI-only initial-account requirement; CLI provisioning remains available.
